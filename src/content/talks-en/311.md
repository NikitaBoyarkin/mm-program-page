The main bottleneck in handling ad-hoc requests is often not writing SQL code but translating a business statement into a strict analytical task. Every unrecorded agreement about filters, cuts and constraints generates new rounds of discussion and returns for recalculation. To solve this problem, the Veborama team built an AI agent. On input it receives an unstructured request in business language, and on output it produces a complete package of artifacts: a formalized statement of the task, a list of metrics, a data work plan and a draft SQL code.

The agent is integrated on top of the company's existing data landscape, including available marts, ELT modules and a library of automated validation rules. It does not replace the analyst but acts as a preprocessor: it surfaces ambiguities in requirements at an early stage and prepares a set of checks relevant to the specific request. Using a real case, the talk breaks down the architecture of this solution, the logic of automatic selection of data quality tests (integrity, event sequence, anomalies), as well as typical mistakes and the agent's operational limits.

Attendees will get a scheme for embedding an AI agent into the request-processing pipeline, including automated quality control and human checkpoints. The talk will show the measurable effect of formalizing tasks through AI: a lower share of returns for rework, time saved on data preprocessing and a multiple increase in analyst throughput.
