# tests/

Два набора, оба на bun. Первый — без браузера и без сборки, второй — на собранной странице.

```bash
bun test                # tests/lib — 66 юнит-тестов ядра (4 файла)
bun run test:built      # tests/built — браузерные тесты (Playwright + astro preview)
```

## `tests/lib` — ядро без DOM

`bun test` гоняет чистые функции `src/lib/program.ts`, `src/lib/ics.ts` и
`src/lib/analytics.ts` против реального слепка `src/data/program.json`.

`program.test.ts` (33 теста):

- инварианты данных: 3 дня в порядке `order`, 91 доклад, 11 треков, 9 залов, форма `HH:MM`,
  `image`/`photo` — либо `https://…`, либо `null`, в текстах нет HTML-тегов и сущностей,
  `day.halls ⊆ halls`, уникальность id;
- `minutes` / `isTime` (валидные и мусорные значения, включая `25:00`), `startsOf`, `spanOf`
  на 2–3 строки, `placeTalks` (коллизия в одном зале и времени → `collisions`, укорачивание
  предыдущего слота при пересечении), `occupiedCells`, `pluralTalks(1|2|5|11|21|22|25)`,
  `dayLabel`, `dayLongLabel`, `resolveDay` (id / дата / номер / мусор), `dayHref`,
  `hallsOfDay`, `tracksOfProgram`, `isPlaceable`.

`theme.test.ts` (4 теста): три hex для `meta[name=theme-color]` совпадают с
`--background-primary` каждой темы в `tokens.css`; `Base.astro` повторяет те же три значения
в инлайновых скриптах; `nextTheme` крутит цикл и переживает мусор в `localStorage`.

`ics.test.ts` (19 тестов): экранирование `\ ; ,` и переводов строк, перенос строки по
75 **октетам** UTF-8 (кириллица не рвётся посередине символа), `icsDate`/`icsStamp`,
`buildCalendar` со стабильным `now` (VTIMEZONE, `DTSTART;TZID=Europe/Moscow`, `DTEND`,
`SUMMARY`, `LOCATION`, `DESCRIPTION`, CRLF, число `VEVENT` = числу докладов), `calendarFilename`,
уникальность `UID`.

`analytics.test.ts` (10 тестов): `parseUtm` (пять параметров, мусор и чужие параметры
игнорируются, значение обрезается до 100 символов), `classifyReferrer` (`direct`, известные
хосты, `other`, битый `referrer` не бросает), `computeFirstTouch` (класс, путь входа и UTM
собираются вместе).

## `tests/built` — сборка в браузере

`playwright.config.ts` поднимает `astro preview` на `127.0.0.1:4321` и проверяет `dist/`,
то есть именно то, что уедет на хостинг. Перед прогоном нужен `bun run build`.

Набор идёт в трёх проектах — один и тот же файл, три окна:

| Проект | Окно | Что покрывает |
| --- | --- | --- |
| `chromium` | 1280×900, Chromium | десктопная сетка «время × залы», широкая строка вкладок, `.ics`, `@media print`; базовый прогон всех 27 тестов |
| `chromium-mobile` | 320×700, Chromium, `isMobile`, `hasTouch`, DPR 3 | нижняя граница мобильной модели: вкладки дней в строку, липкая цепочка, отсутствие горизонтального скролла |
| `webkit-iphone` | 390×844, WebKit, iPhone 13 (`devices["iPhone 13"]`) | второй движок: `position: sticky` крестика модалки, `inert`, `history.pushState`/`popstate`, CSS `:has()`, сенсорные состояния |

Мобильные тесты 09–18 задают ширину сами (`test.use({ viewport })` в группе
«мобильный 390×844», а тесты 320 px — в группе «мобильный 320×700»), поэтому идут в обоих
мобильных проектах. Мобильная модель включается CSS-медиазапросом `max-width: 767.98px`,
других переключателей нет.

Что проверяется: 39 / 37 / 15 карточек на трёх страницах и 91 уникальный `data-talk-id`;
активный таб; чистая консоль; фильтр с `?track=`, счётчиком и снятием; избранное с
перезагрузкой; модалка с фокус-трапом и возвратом фокуса; скачанный `.ics` с 39 `VEVENT`;
drawer; три темы (тумблер в шапке и тумблер в drawer'е, оба живут одновременно);
`/program.json`; тумблер темы в шапке на 1440 px без открытия меню; печать
(`@media print` не скрывает заголовок карточки без баннера); прогон с
`javaScriptEnabled: false` (HTML-first) на десктопе и на 390 px; крестик модалки как
`position: sticky` после прокрутки длинного описания; системная «Назад» закрывает модалку;
`prefers-reduced-motion: reduce`; кнопка-заголовок карточки (текст = название, высота ≥ 44 px)
в списке и в сетке; три вкладки дней на 320 px без переполнения; липкая цепочка
«шапка → вкладки дня → разделитель времени» при `scrollY = 0` и на 320 px.

Мобильная группа (390 × 844) проверяет не «сжалась ли сетка», а саму модель списка:

- у документа нет горизонтального overflow и нет горизонтального скролла внутри сетки —
  контент живёт в одной оси;
- карточки идут одним столбцом в хронологическом порядке и в DOM-порядке строк;
- шапка залов не отрисована, зал читается бейджем `.talk-card__hall` внутри карточки;
- баннер у карточки с картинкой скрыт, а у `.talk-card--compact` заголовок с кнопкой
  открытия модалки на месте;
- время в карточке скрыто, его несёт липкий разделитель `.program-grid__time-cell`,
  который стоит под табами дня, а табы — под шапкой;
- чип «Избранное» первым в `.track-chips`, считает избранное, складывается с фильтром
  трека по «И», а в URL по-прежнему попадает только `?track=`;
- в режиме списка группа времени без видимых докладов прячет свой разделитель.

Число тестов здесь не названо намеренно: набор мобильной группы ещё дописывается, и
любая цифра устареет раньше, чем её прочтут. Источник истины — `grep -c "test("
tests/built/program.spec.ts`.

## Мобильный бюджет

Lighthouse в мобильном режиме: **390 px, Slow 4G** (эмуляция Moto G / iPhone-класса,
throttling 1.6 Мбит/с, RTT 150 мс). Порог, ниже которого сборка не считается готовой:

| Метрика | Бюджет |
| --- | --- |
| Performance | ≥ 90 |
| LCP | ≤ 2.5 с |
| CLS | ≤ 0.1 |
| INP | ≤ 200 мс |

Бюджет — это контракт страницы, а не тест: Playwright проверяет разметку и поведение, а
метрики снимает Lighthouse на том же `dist/` (`bun run build` → `bunx astro preview`).
Отдельного проекта в `playwright.config.ts` под Lighthouse нет намеренно: метрики меряются
один раз на релиз, а не на каждый прогон, иначе набор перестаёт быть детерминированным.

Мобильные проекты покрывают разное, и это не дубль:

- `chromium-mobile` (320×700) — ширина, на которой ломается строка вкладок и липкая цепочка:
  три таба дня, `scrollWidth - clientWidth = 0` у `.day-tabs` и документа, разделитель
  времени не заезжает под табы;
- `webkit-iphone` (390×844, iPhone 13) — второй движок: `position: sticky` крестика
  модалки внутри прокручиваемого диалога, `history.pushState`/`popstate` для закрытия
  системной «Назад», `inert` на фоне, `:has()` для блокировки прокрутки под drawer'ом.

Две настройки конфига выглядят странно и обе вынуждены:

- `webServer.env.ASTRO_PREVIEW_BACKGROUND = "1"` — Astro 7 при детекте агентского окружения
  уводит `preview` в фон и выходит с кодом 0, Playwright падает с «exited early».
- `use.colorScheme: "dark"` — иначе предрисуночный скрипт темы ставит светлую тему и тест
  цикла темы проверяет не тот старт.

Третья особенность — WebKit на macOS: Tab не доходит ни до кнопок, ни до ссылок (поведение
Safari по умолчанию), поэтому фокус-трап модалки в проекте `webkit-iphone` проверяется
событием `keydown` из DOM, а в Chromium-проектах — настоящими нажатиями клавиши. Проверяемое
поведение (фокус остаётся в `[data-modal-dialog]`, Tab с последнего элемента уводит на
первый, Shift+Tab с первого — на последний) одинаково.

Если WebKit не установлен, тесты проекта `webkit-iphone` не стартуют: `bunx playwright install
webkit` (нужна сеть, ~79 МБ). Проект из конфига не удаляется — иначе WebKit-регрессии
перестают ловиться вовсе.

Если `preview` остался висеть после ручного запуска, следующий прогон упрётся в «preview
already running» — снимите лок: `bunx astro preview stop`.

Третья особенность — не конфиг, а `test.beforeEach` в спеке: внешние запросы (баннеры и фото
спикеров с CDN первоисточника) получают 1×1 PNG, остальные гасятся. Без этого `load` ждал все
чужие картинки, и прогон флакал на таймауте (20.7 с на одном тесте); с этим — весь набор за
8–10 с. Именно PNG, а не `abort`: прерванный запрос Chromium пишет в консоль как ошибку
ресурса, а тест `04` требует чистую консоль.

## Мутационный контроль

Наборы падают от реальных дефектов, а не только от «правильного» входа:

- порча слепка (удалён доклад, HTML в заголовке, переставлены залы) валит 4 юнит-теста;
- переименование `data-talk-id` или удаление `[data-favorites-count]` валит браузерные
  счётчики и тест избранного (именно так был найден отсутствовавший счётчик в v2).
