# Решения и отклонения

Журнал: что сделано, почему именно так и где копия осознанно расходится с оригиналом.
Обновлять при любом изменении поведения.

## 0. История версий

- **v1** (коммит `1f35b05`) — статика без сборки: `index.html`, `assets/styles.css`,
  `assets/app.js`, `data/program.js`, тесты на Python + headless Chrome. Открывалась
  двойным кликом по `file://`.
- **v2** (текущая) — Astro 7 + Bun. `file://` больше не работает: у страницы есть роуты,
  ассеты с хешами и JSON-эндпоинт, им нужен сервер (`bun run preview`) или хостинг.
  Файлы v1 удалены из рабочего дерева, не из истории: `git show 1f35b05:index.html`,
  `git show 1f35b05:assets/app.js`, `git show 1f35b05:tools/fetch_program.py`.

Почему переписали: v1 доказывал умение измерить и повторить чужой интерфейс, но не
показывал сборку. Сетка на 91 карточку рендерилась в браузере, то есть без JS страница
показывала пустой каркас, а три дня программы не имели адресов. Astro даёт ровно то, чего
не хватало: HTML на билде, по URL на день, типы и тесты без браузера.

## 1. Что рендерится на билде, а что в браузере

**На билде:** вся сетка, карточки, табы дней, чипы треков, счётчик, шапка дня, факты,
подвал. `getStaticPaths` в `src/pages/day/[n].astro` выдаёт по странице на день, `index.astro`
рендерит первый.

**В браузере** (`src/scripts/program-client.ts`, 32.6 КБ raw / 12.8 КБ gzip по `gzip -9`
на собранном `dist/_astro/ProgramPage…js`) — только то, что
обязано реагировать на ввод после первой отрисовки: переключение темы с морфом иконки,
drawer, фильтры (трек и «Избранное»), хранение избранного в `localStorage`, модалка
доклада, `.ics`. Фреймворка нет: свой код — один TS-модуль плюс `morphicons` в том же
чанке, который Astro подключает к странице программы (на `404` он не грузится).

Проверено тестом `13` с `javaScriptEnabled: false`: 39 карточек, 3 таба и 11 чипов на месте.
Это и есть причина, по которой выбрана Astro, а не SPA.

## 2. День — это URL, а не состояние в памяти

v1 переключала день кнопкой и перерисовывала DOM. v2 отдаёт `/`, `/day/2/`, `/day/3/` — три
пререндеренные страницы. Плата: переход по дню — навигация, а не мгновенная перерисовка.
Выигрыш: каждая страница печатается, шарится и открывается без JS; браузер кеширует её
отдельно; `?track=` остаётся единственным состоянием, которое живёт в query.

Фильтр по трекам остался клиентским: 3 дня × 11 треков дали бы 33 страницы на 91 доклад —
это больше HTML, чем пользы. При активном фильтре ячейки чужого трека получают `hidden`,
пустые ячейки остаются: геометрия сетки не рушится, и это видно в тесте `05`.

## 3. Данные: один слепок, два потребителя

`src/data/program.json` — единственный источник. Из него читают билд (`src/lib/program.ts`)
и клиент (`/program.json`, тот же файл через эндпоинт). Данные не вшиты в клиентский бандл:
32.6 КБ скрипта не растут вместе с программой, а 280 КБ JSON (60.5 КБ gzip) грузятся лениво —
только при первом открытии модалки или экспорте `.ics`.

Нормализация живёт в `scripts/fetch-program.ts` (порт `tools/fetch_program.py`). Запись
стабильная (2 пробела + перевод строки), поэтому `bun run data:check` — побайтовое сравнение
с закоммиченным `data/program.raw.json`: расхождение = exit 1 + unified diff. Единственное
исключённое поле — `generatedAt` (ставится в момент сборки, маскируется в обеих сторонах,
иначе проверка была бы красной всегда). Живой API `--check` не трогает: сеть — только у
`--fetch`, который пишет сначала raw, потом слепок, поэтому падение между записями ловится
следующим `--check`.

## 4. Сетка: замороженные метрики и один честный сдвиг

Измерено в Chromium на собранной странице, `1440×900`:

| Метрика | Оригинал | v1 | v2 | Статус |
| --- | ---: | ---: | ---: | --- |
| Колонка времени | 99 px | 99–100 px | 100 px | совпадает |
| Колонка зала | 420 px | 420 px | 420 px | совпадает |
| Карточка | 391 px | 391 px | 391 px | совпадает |
| Радиус карточки | 16 px | 16 px | 16 px | совпадает |
| Баннер | 4:3 | 4:3, 291 px | 389×292 px (4:3) | **шире** |
| Строка сетки | 550 px | 550 px | 520–643 px | **выше** |
| Верх сетки | y = 414 | y = 414 | y = 527 | **ниже** |
| Высота документа | 6605 px | 6589 px | 7475 px | **выше** |

Причины сдвига, все три — следствие переезда на дизайн-систему, а не «поехавшая вёрстка»:

1. Баннер тянется на всю ширину карточки (`aspect-ratio: 4/3`), поэтому при карточке 391 px
   он 389×292 вместо 291 px по ширине. Пропорция сохранена, коробка больше.
2. Строка сетки — `minmax(520px, auto)`: она растёт под самую высокую карточку, а карточки
   стали выше из-за баннера. Отсюда 520–643 px: минимум 520 плюс контент самой высокой карточки в строке.
3. Над сеткой появилась шапка страницы (заголовок, интро, факты) и тулбар с чипами —
   сетка начинается на y = 527 вместо y = 414.

Уже 1280 px: время 70 px, зал `minmax(310px, 390px)`, сетка скроллится внутри контейнера,
колонка времени и шапка залов sticky. Мобильный экран устроен иначе — не сжатая сетка,
а хронологический список, см. §10.

## 5. Палитра и шрифты: дизайн-система портфолио, не бренд Матемаркетинга

Взята палитра `NikitaBoyarkin.github.io` (`DESIGN.md`): индиго / крем / киберпанк, акцент
только на интерактив, тёмная тема по умолчанию. Токены перенесены в `src/styles/tokens.css`
как есть, включая пометки о том, почему на тёмной теме шаг поверхностей идёт **вниз**.

Следствия, которые нужно держать в голове:

- **Контраст WCAG здесь не гейтится.** В эталонном репозитории пары проверяет хук
  `contrast-gate.js`; в этом проекте его нет, поэтому «AA подтверждён» — утверждение про
  источник палитры, а не про этот репозиторий.
- **Шрифты self-hosted**: Inter и Cormorant (OFL) лежат в `src/assets/fonts` (через бандлер: хеш + префикс `base`), четыре подмножества
  каждый. Google Fonts и CDN Матемаркетинга не используются, Loos Wide не распространяется.
- **Логотип конференции не воспроизводится как файл**: чёрный SVG на индиго невидим, поэтому
  в шапке стоит знак портфолио, а принадлежность страницы задаётся текстом. Знак — монограмма
  из `favicon.svg`: шестиугольник с вырезанными «NB». В шапке она живёт CSS-маской с
  `currentColor` (как остальные иконки), поэтому читается во всех трёх темах без второго цвета;
  глифы сняты с Inter 800 и лежат путями — маска это отдельный документ, веб-шрифт страницы
  ей недоступен. Ширину держит `aspect-ratio` шестиугольника (92×79.6), а на телефоне
  (≤ 479.98 px) — прежняя рамка 25×28: монограмма на 7 px шире звёздочки, а на 390 px полоса
  под имя ровно 108 px.

## 6. Карточка и модалка: доступность вместо «div с обработчиком»

- Карточка не имеет `tabindex`: модалку открывает настоящий `button.talk-card__title-btn`
  вокруг заголовка. Это даёт фокус, `Enter`/`Space` и имя для скринридера бесплатно.
- «Подробнее» рендерится только там, где текст реально не влезает в кламп (> 240 символов —
  66 карточек из 91). Кнопка без видимого эффекта хуже её отсутствия.
- Модалка: `role="dialog"`, `aria-modal`, фокус-трап по Tab внутри диалога, `Esc`, клик по
  подложке, возврат фокуса на кнопку-триггер, `body.is-modal-open` держит лок скролла.
- Тексты из данных попадают в DOM только через `textContent`/`createElement`: `innerHTML`
  в клиенте не используется ни разу.
- Изображения с чужого CDN получают `referrerpolicy="no-referrer"` и проходят проверку
  «только `https:`» — поле из чужого API не должно стать beacon'ом.

## 8. Пути строятся от `BASE_URL`, шрифты идут через бандлер

Первая версия этого переписывания жёстко писала `/program.json`, `/fonts/…` и `/day/2/` —
работало только на корне домена. При `base: "/mm-program-page"` всё ломалось: ссылки дней
склеивались в `/mm-program-pageday/2/`, `/program.json` и шрифты уходили в 404, favicon тоже.

Что сделано: `BASE_URL` в `src/lib/program.ts` (нормализованный `import.meta.env.BASE_URL`
с фолбэком для `bun test`), `dayHref` и клиентский `fetch` строятся от него, favicon
префиксуется в `Base.astro`, а шрифты переехали из `public/fonts` в `src/assets/fonts` —
только оттуда Vite переписывает `url()` на хешированный путь с префиксом. Проверка не «на
глаз»: сборка с `base` прогнана в Chromium, табы ведут на `/mm-program-page/day/2/`, модалка
открывается (значит `/program.json` отдался 200), шрифты загрузились 200, консоль чистая.

Цена: `public/fonts` больше не годится как способ положить шрифт, и `?track=` резолвится по
чипам, а не через `resolveTrack` из ядра (та функция тянет статический `PROGRAM` и втянула бы
280 КБ слепка в клиентский бандл ради одного сравнения).

## 10. Мобильный экран: список вместо сжатой сетки

До 767.98 px в кадр помещается один зал. Пять колонок залов на 390 px дают ширину
содержимого 2020 px против 358 px вьюпорта — около 5.7× того, что видно, уезжает за
горизонтальный скролл, а человек видит колонку «Молекула» и ничего больше. Поэтому
мобильная модель — не сжатая сетка, а **хронологический список**.

Переключает её только CSS, разметка одна. `.program-grid__content` становится
`display: flex; flex-direction: column`, а DOM уже идёт в порядке строк (время → доклады
строки по залам → следующее время), поэтому список получается бесплатно, а inline
`grid-area` в не-grid контейнере инертен. Второго HTML, второго маршрута и второй копии
карточек нет; без JS список читается целиком.

| Что | На мобильном | Почему так |
| --- | --- | --- |
| `.program-grid` | `overflow: visible`, без `min-inline-size` | скроллить нечего: контент живёт в одной оси |
| `.program-grid__content` | flex-столбец | строки сетки исчезают, остаётся один столбец |
| Шапка залов | `display: none` | столбца залов больше нет — подписывать нечего |
| Зал | бейдж `.talk-card__hall` в карточке | зал — свойство доклада, а не координата; на десктопе бейдж скрыт, там зал читается из шапки |
| Баннер | скрыт у карточки с картинкой | баннер 4:3 оттесняет текст на пол-экрана, а картинку всё равно видно в модалке |
| `.talk-card--compact` | `.talk-card__media` остаётся | в нём `h3` с кнопкой заголовка: скрыть — оставить 13 карточек без заголовка и без входа в доклад |
| Время в карточке | `display: none` | его несёт липкий разделитель группы |
| Разделитель времени | липкий заголовок группы, а не колонка | группа времени держит ориентацию при скролле |

Липкая цепочка: `header.nav-mobile` (0…65 px) → `nav.day-tabs` (65…126 px; 61 px = таб
44 + два паддинга по 8 + линия 1) → разделитель времени (`top` = 126 px). Смещение каждой
ступени — сумма высот предыдущих, посчитанная из `--nav-mobile-h` и `--mm-day-tabs-h`,
поэтому разделитель не заезжает под табы дня, а табы — под шапку.

**«Избранное» — второй, независимый фильтр.** Чип `button.track-chip[data-fav-filter]`
стоит первым в `.track-chips` и намеренно не несёт `data-track`, поэтому селектор чипов
трека его не подхватывает, а счётчик в чипе живёт рядом с `[data-favorites-count]`.
Условия складываются по «И»: видима ячейка, у которой (трек не выбран или совпал) и
(фильтр избранного выключен или доклад в избранном). В URL попадает только `?track=`:
избранное лежит в `localStorage`, и ссылка с чужим избранным была бы ложью. В режиме
списка группа времени без видимых докладов прячет свой разделитель — липкий ярлык без
содержимого мусорит; в сетке разделители не скрываются никогда, иначе рвётся колонка
времени.

**Цена.** Замерено в Chromium, `390×844`, день 1 (39 карточек, пять залов):

| Метрика | Сжатая сетка | Список |
| --- | ---: | ---: |
| Ширина документа | 390 px, `scrollWidth` сетки 2020 | 390 / 390 px, горизонтального скролла нет |
| Помещается в кадр | один зал из пяти | вся ширина карточки |
| Скрыто за горизонтальным скроллом | ~5.7× содержимого | 0 |
| Высота документа | 7 479 px | 15 454 px |

В списке 39 карточек в один столбец, высота карточки 256…468 px, средняя 347. Документ
стал в 2.1 раза выше — это плата за то, что каждая карточка видна целиком. Скрытые 5.7×
ширины в сетке не были экономным экраном: там был один зал и надежда, что человек
догадается скроллить вбок.

Снимки одного и того же дня 1 при `390×844`: [до, сжатая сетка](./screenshots/mobile-grid.png)
(390×7 399 — в кадре одна колонка зала, остальные четыре за горизонтальным скроллом)
и [после, список](./screenshots/mobile.png) (390×15 454 — все 39 докладов в одной оси).

Десктоп не изменился: `1440×900` — карточка 391 px, 5 колонок,
баннер виден, высота документа 7 475 px (§4).

### Осознанные решения волны 3

- **Фильтр по треку на телефоне — нативный `select`, а не чипы.** Двенадцать подписей
  занимают 2147 px: в строку 358 px они не влезают, перенос даёт 8 строк / 252 px над
  карточками, а перенос в 10 px — 5 строк, но кегль мельче принятого минимума. Поэтому
  на ≤ 767.98 px чипы треков скрыты, а тот же `activeTrack` выбирается системным списком
  в одну строку 36 px внутри `label.track-select` (чип «Избранное» остаётся чипом).
  Оба вида читают и пишут одно состояние: `aria-pressed` скрытых чипов продолжает
  обновляться, `change` списка зовёт тот же `setActiveTrack`.
- **Маска-градиент на вкладках не нужна.** Ряд вкладок на 320 px встаёт в строку целиком
  (тест `20`), скрывать fade-краем нечего; лишний слой градиента не заводим.
- **Крестик модалки — `sticky` с `inset-block-start: 0`.** `absolute` уезжал вместе с
  контентом при прокрутке длинного описания. `sticky` отсчитывается от content-box,
  поэтому `var(--space-3)` = 12 px складывались с 16 px паддинга диалога — кнопка висела
  в 29 px от края; ноль возвращает её к самому верху.
- **`flex: none` у крестика.** В колоночном flex-контейнере кнопка сжималась до 22 px
  на длинном докладе — цель нажатия ломалась. `flex: none` держит видимый круг 40 px
  (44 px с псевдоэлементом).
- **Два тумблера темы.** Тема перестала зависеть от drawer'а: на мобиле открывать меню
  ради смены темы — лишний шаг. Старый тумблер остался в `.drawer-foot`, новый — в
  `div.nav-top-actions` шапки; оба несут `data-theme-toggle`, поэтому слушатель один
  и делегирован.
- **`history`-стек для слоёв.** Модалка и drawer открываются с `pushState`, системная
  «Назад» закрывает слой через `popstate`; пользовательское закрытие делает
  `history.back()`, но только если верхняя запись ещё наша (`mmLayerToken`) — иначе
  `back()` увёл бы со страницы.
- **`inert` через `MutationObserver`, а не из клиента.** Модалка — отдельный
  Astro-компонент, а класс `body.is-modal-open` ставит `program-client.ts`. Наблюдатель
  за `class` держит компонент независимым от порядка инициализации и не требует
  экспортировать из клиента функцию «заблокируй фон». Снятие `inert` синхронно в
  capture-фазе возвращает уже `inert`-drawer'у его прежнее состояние.
- **`html:has()` для iOS.** `overflow: hidden` на `body` не гасит «резину» корневого
  скроллера в WebKit; дубль `html:has(body.nav-open)` и `html:has(body.is-modal-open)`
  адресует корневой скроллер напрямую. `:has()` уже в базовой линии проекта.

## 11. Иконка темы: морф вместо статичной луны

Тумблеров темы два (шапка и drawer), тема циклится dark → light → cyberpunk, но в разметке
на все три состояния стояла одна луна: `.astro` рендерится на билде и о `localStorage` не
знает, а клиент иконку не трогал. В светлой теме луна врала о состоянии.

**Решение.** `morphicons@1.7.0`, subpath `morphicons/dom`: `createMorph(path, d)` на каждый
тумблер, `morphTo` в делегированном обработчике. Иконки — сырые `d` строки: `IconInput`
имеет строковую ветку, пакет данных с иконками не нужен. Первая иконка ставится без
анимации, поэтому сохранённая тема сразу даёт своё состояние.

**Почему не `morphicons/astro` + `element`.** Потребовал бы заменить `<path>` на
`<MorphIcon>` в двух компонентах, весит 8.9 КБ gzip вместо 7.1 и добавляет второй
скрипт-чанк. `dom` живёт в уже подключённом модуле и разметку не меняет — прогон без JS
(тест `13`) остаётся прежним.

**Звезда избранного — не морф.** Пайплайн 1.7.0 штриховой: залитая фигура разбирается, но
в полёте читается неправильно (fill-конвейер появился только в 2.x). Поэтому контур →
заливка сделана через CSS: постоянный `fill: currentColor` + `fill-opacity: 0 → 1`. `fill`
между `none` и цветом не интерполируется, `fill-opacity` — интерполируется. Строка
`path.setAttribute("fill")` из `syncFavorites` удалена: источник состояния теперь один.

**Цена.** Клиентский чанк 17.0 → 32.6 КБ raw (6.2 → 12.8 КБ gzip). HTML не изменился:
иконки остаются в разметке, CSS вынесен отдельными файлами, инлайновых `<style>` нет.
`reducedMotion: "user"` — при системной настройке «уменьшить движение» морф заменяется
мгновенной подменой, как и остальные переходы в CSS.

**Проверено.** `bun run check` — 0 ошибок; `bun test` — 66 pass; Playwright — 81 pass,
включая прогон с выключенным JavaScript.

## 12. Языки: ручные маршруты и overlay перевода

Нужны две локали без второго фреймворка и без правки замороженного снапшота. Русская
версия остаётся первичной: `/`, `/day/N/`, `/program.json`.

**Решение.** Язык — это маршрут, а не настройка. `src/pages/en/index.astro` и
`src/pages/en/day/[n].astro` повторяют русскую раскладку (первый день — на корне локали),
`src/i18n/paths.ts` строит адреса от `BASE_URL`, `src/pages/en/program.json.ts` отдаёт
переведённый слепок. `<html>` несёт `lang` и `data-lang`, у страниц дня есть
`hreflang="ru|en"` и `x-default` → русская версия. Оболочка переводится словарём
`src/i18n/ui.ts`, контент — overlay'ем `src/data/program.en.json`.

**Почему не `i18n`-конфиг Astro.** Встроенная маршрутизация (`prefixDefaultLocale`,
`redirectToDefaultLocale`) добавила бы правила для адресов, которых у нас нет: 404 и JSON
не должны получать префикс автоматически, а первый день живёт на корне локали, а не в
`day/1/`. Ручные страницы — это четыре файла примерно по 20 строк, и адреса остаются явными.

**Почему overlay, а не перевод в `program.json`.** `bun run data:fetch` пересобирает
`program.json` побайтово из API и стёр бы переводы — та же причина, по которой отдельным
файлом живут соцсети. Overlay адресуется по id доклада и хранит только текст:
`title/short/description/lectorRoles`. Пропуск — не ошибка: `localizeTalk` возвращает
исходную русскую строку, страница рендерится с неполным переводом, а не падает.

**Почему `data-track` остаётся русским.** По этому атрибуту клиент фильтрует сетку и
связывает карточку с чипом; переведённое значение сломало бы селектор. Поэтому
`localizeTalk` переводит только текстовые поля, а подпись чипа и текст на карточке
переводятся отдельно (`trackLabel`). `localizeProgram` — отдельная функция для
`/en/program.json`: там `track`, `hall` и `days[].halls` уже переведены, потому что модалка
и `.ics` читают JSON как готовый текст.

**Машинный перевод — принятое ограничение.** Английские тексты докладов получены машинным
переводом и не сверялись с авторами; исходный русский `program.json` остаётся источником
истины. Это записано в `CONTRACT.md`, чтобы расхождение не выдавалось за редактуру.

**Цена.** Overlay — 146 379 байт raw / 43 312 байт gzip (`gzip -9 -c
src/data/program.en.json | wc -c`), но в браузер он не уезжает: перевод применяется на
билде. Клиентский чанк вырос с 310.8 до 323.8 КБ raw (76.6 → 79.6 КБ gzip) — поиск и
словарь. HTML дня — 172.8 КБ raw / 23.9 КБ gzip.

**Проверено.** `bun test tests/lib` — 117 pass в 6 файлах, включая `tests/lib/i18n.test.ts`
(покрытие overlay'я 91/91, неизменность ссылочных полей) и `tests/lib/search.test.ts`.
E2E-набор `tests/built/i18n-search.spec.ts` — 8 тестов; вместе с `program.spec.ts` это
36 тестов в трёх проектах (108 прогонов), прогон — отдельной командой `bun run test:built`.
