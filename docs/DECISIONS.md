# Решения и отклонения

Журнал: что сделано, почему именно так и где копия осознанно расходится с оригиналом.
Обновлять при любом изменении поведения.

## 0. История версий

- **v1** (коммит `1f35b05`) — статика без сборки: `index.html`, `assets/styles.css`,
  `assets/app.js`, `data/program.js`, тесты на Python + headless Chrome. Открывалась
  двойным кликом по `file://`.
- **v2.1** (текущая) — граф докладов переехал в этот сайт (`/talks/`, `/en/talks/`) и вырос
  из «пункта в меню» до трёх поверхностей в шапке (`§15`, `§20`); на телефоне тулбар
  избавлен от дублей фильтров (`§21`).
- **v2.0** — Astro 7 + Bun. `file://` больше не работает: у страницы есть роуты,
  ассеты с хешами и JSON-эндпоинт, им нужен сервер (`bun run preview`) или хостинг.
  Файлы v1 удалены из рабочего дерева, не из истории: `git show 1f35b05:index.html`,
  `git show 1f35b05:assets/app.js`, `git show 1f35b05:tools/fetch_program.py`.

Почему переписали: v1 доказывал умение измерить и повторить чужой интерфейс, но не
показывал сборку. Сетка на 91 карточку рендерилась в браузере, то есть без JS страница
показывала пустой каркас, а три дня программы не имели адресов. Astro даёт ровно то, чего
не хватало: HTML на билде, по URL на день, типы и тесты без браузера.

## 1. Что рендерится на билде, а что в браузере

**На билде:** вся сетка, карточки, табы дней, чипы треков, счётчик, шапка дня, факты,
подвал. `getStaticPaths` в `src/pages/day/[n].astro` выдаёт по странице на день, `index.astro`
рендерит первый.

**В браузере** (`src/scripts/program-client.ts`, 46.6 КБ raw / 17.6 КБ gzip по `gzip -9`
на собранном `dist/_astro/ProgramPage…js`) — только то, что
обязано реагировать на ввод после первой отрисовки: переключение темы с морфом иконки,
drawer, фильтры (трек и «Избранное»), хранение избранного в `localStorage`, модалка
доклада, `.ics`. Фреймворка нет: свой код — один TS-модуль плюс `morphicons` в том же
чанке, который Astro подключает к странице программы (на `404` он не грузится).

Проверено тестом `13` с `javaScriptEnabled: false`: 39 карточек, 3 таба и 11 чипов на месте.
Это и есть причина, по которой выбрана Astro, а не SPA.

## 2. День — это URL, а не состояние в памяти

v1 переключала день кнопкой и перерисовывала DOM. v2 отдаёт `/`, `/day/2/`, `/day/3/` — три
пререндеренные страницы. Плата: переход по дню — навигация, а не мгновенная перерисовка.
Выигрыш: каждая страница печатается, шарится и открывается без JS; браузер кеширует её
отдельно; `?track=` остаётся единственным состоянием, которое живёт в query.

Фильтр по трекам остался клиентским: 3 дня × 11 треков дали бы 33 страницы на 91 доклад —
это больше HTML, чем пользы. При активном фильтре ячейки чужого трека получают `hidden`,
пустые ячейки остаются: геометрия сетки не рушится, и это видно в тесте `05`.

## 3. Данные: один слепок, два потребителя

`src/data/program.json` — единственный источник. Из него читают билд (`src/lib/program.ts`)
и клиент (`/program.json`, тот же файл через эндпоинт). Данные не вшиты в клиентский бандл:
46.6 КБ скрипта не растут вместе с программой, а слепок на 298 511 байт (62 932 байта gzip)
грузится лениво — клиент префетчит его на первом взаимодействии (`pointerdown`/`keydown`),
а поиск запрашивает его сразу при открытии. Разделение модулей, которое это держит, —
в §13.

Нормализация живёт в `scripts/fetch-program.ts` (порт `tools/fetch_program.py`). Запись
стабильная (2 пробела + перевод строки), поэтому `bun run data:check` — побайтовое сравнение
с закоммиченным `src/data/program.json`: расхождение = exit 1 + unified diff. Сырой
`data/program.raw.json` — только вход пересборки, а сравнение идёт с нормализованным слепком.
Единственное
исключённое поле — `generatedAt` (ставится в момент сборки, маскируется в обеих сторонах,
иначе проверка была бы красной всегда). Живой API `--check` не трогает: сеть — только у
`--fetch`, который пишет сначала raw, потом слепок, поэтому падение между записями ловится
следующим `--check`.

## 4. Сетка: замороженные метрики и один честный сдвиг

Измерено в Chromium на собранной странице, `1440×900`:

| Метрика | Оригинал | v1 | v2 | Статус |
| --- | ---: | ---: | ---: | --- |
| Колонка времени | 99 px | 99–100 px | 100 px | совпадает |
| Колонка зала | 420 px | 420 px | 420 px | совпадает |
| Карточка | 391 px | 391 px | 391 px | совпадает |
| Радиус карточки | 16 px | 16 px | 16 px | совпадает |
| Баннер | 4:3 | 4:3, 291 px | 389×292 px (4:3) | **шире** |
| Строка сетки | 550 px | 550 px | 520–643 px | **выше** |
| Верх сетки | y = 414 | y = 414 | y = 527 | **ниже** |
| Высота документа | 6605 px | 6589 px | 8260 px | **выше** |

Причины сдвига, все три — следствие переезда на дизайн-систему, а не «поехавшая вёрстка»:

1. Баннер тянется на всю ширину карточки (`aspect-ratio: 4/3`), поэтому при карточке 391 px
   он 389×292 вместо 291 px по ширине. Пропорция сохранена, коробка больше.
2. Строка сетки — `minmax(520px, auto)`: она растёт под самую высокую карточку, а карточки
   стали выше из-за баннера. Отсюда 520–643 px: минимум 520 плюс контент самой высокой карточки в строке.
3. Над сеткой появилась шапка страницы (заголовок, интро, факты) и тулбар с чипами —
   сетка начинается на y = 527 вместо y = 414.

Уже 1280 px: время 70 px, зал `minmax(310px, 390px)`, сетка скроллится внутри контейнера,
колонка времени и шапка залов sticky. Мобильный экран устроен иначе — не сжатая сетка,
а хронологический список, см. §10.

## 5. Палитра и шрифты: дизайн-система портфолио, не бренд Матемаркетинга

Взята палитра `NikitaBoyarkin.github.io` (`DESIGN.md`): индиго / крем / киберпанк, акцент
только на интерактив, тёмная тема по умолчанию. Токены перенесены в `src/styles/tokens.css`
как есть, включая пометки о том, почему на тёмной теме шаг поверхностей идёт **вниз**.

Следствия, которые нужно держать в голове:

- **Контраст WCAG здесь не гейтится.** В эталонном репозитории пары проверяет хук
  `contrast-gate.js`; в этом проекте его нет, поэтому «AA подтверждён» — утверждение про
  источник палитры, а не про этот репозиторий.
- **Шрифты self-hosted**: Inter и Cormorant (OFL) лежат в `src/assets/fonts` (через бандлер: хеш + префикс `base`), четыре подмножества
  каждый. Google Fonts и CDN Матемаркетинга не используются, Loos Wide не распространяется.
- **Логотип конференции не воспроизводится как файл**: чёрный SVG на индиго невидим, поэтому
  в шапке стоит знак портфолио, а принадлежность страницы задаётся текстом. Знак — монограмма
  из `favicon.svg`: шестиугольник с вырезанными «NB». В шапке она живёт CSS-маской с
  `currentColor` (как остальные иконки), поэтому читается во всех трёх темах без второго цвета;
  глифы сняты с Inter 800 и лежат путями — маска это отдельный документ, веб-шрифт страницы
  ей недоступен. Ширину держит `aspect-ratio` шестиугольника (92×79.6), а на телефоне
  (≤ 479.98 px) — рамка 25×28: монограмма на 7 px шире звёздочки, а полосы под имя там больше
  нет (см. §16 — звезда «Избранное» в шапке заняла её место).

**Фон страницы — четыре слоя, а не один цвет, и два из них едут.** Это тот же эталон
(`--gradient-page`, `--wallpaper-tile`, `--gradient-hero` в `global.css` портфолио),
перенесённый в `tokens.css`. Плитка сот совпадает с эталоном байт в байт (42×24), а
плотность линии — нет: эталонные 7 % на телефоне не читались — замер по живому сайту в
WebKit-iPhone давал модуляцию 1.5 уровня из 255 на линии в 1 px, — поэтому
`--wallpaper-line` поднят до `rgba(0, 40, 40, 0.24)` / `rgba(255, 253, 245, 0.3)` /
`rgba(0, 40, 40, 0.4)` (ΔY ≈ 3–5 / 5 / 3 уровней). Цвет выбран по **стороне контраста**,
а не только по плотности: слой лежит поверх свечения, и штрих попадает в тот же пиксель,
что и глиф. Поэтому на тёмных темах линия темнее земли, на светлой — светлее; прежняя
светлая бирюза на индиго и тёмная хвоя на креме поднимали (опускали) яркость под буквой и
роняли ссылку/`--text-muted` до 3.58–4.11:1. «Соты как в портфолио» — про геометрию, цвет
и порядок слоёв, а не про альфу:

- канва — `html` с плоским `--background-primary`: её красит rubber-band прокрутка и
  область за пределами фиксированных слоёв;
- ramp `135deg` (`primary → secondary → card`) — фиксированный слой `body::before`;
- свечение акцента — `.ground-bloom`, отдельный фиксированный **элемент** (у `body`
  только два псевдоэлемента, а у света своя фаза движения);
- соты — `body::after`: геометрия одной SVG-плиткой 42×24 в `mask-image`, цвет отдельным
  токеном `--wallpaper-line` (24–40 %), поэтому одна плитка обслуживает все три темы.

**Перетекание земли — порт дрейфа главной страницы портфолио** (`HomeNewTab.astro`,
`.newtab::before`/`::after`). Ramp и свечение едут по замкнутым орбитам: 24 s и 34 s,
движение обратное. Почему так, а не иначе:

- **Движется `transform`, а не `background-position`.** Трансформ уходит на композитор;
  позиция фона перерисовывала бы вьюпорт каждый кадр — та же ловушка, из-за которой соты
  не используют `background-attachment: fixed`.
- **Орбита замкнута и `linear`.** `alternate` ставит на каждом конце разворот и нулевую
  скорость — глаз читает это как отскок, а не как течение.
- **Слой больше вьюпорта на 40 % с каждой стороны** (`inset: -40%`), и это оверскан под
  орбиту: `translate3d` в процентах считается от размера слоя (180 % экрана), то есть
  20 % = 36 % экрана — меньше 40 %, значит край слоя в кадр не входит.
- **Две фазы, а не одна.** Стопы рампы отстоят на один шаг лестницы (в киберпанке два из
  трёх совпадают), поэтому её собственное движение читается как смена яркости, а не как
  текущий цвет. Цвет даёт второе пятно — полной силы `--text-accent` на `opacity`, потому
  что `mix-blend-mode` в этой позиции замеренно инертен (четыре режима меняли кадр на
  ≤2/255 против 46/255 у `normal`: слой на `z-index: −1` смешивается с подложкой, которую
  подкрасить не может).
- **Сила свечения выбрана по контрасту, а не по вкусу, и она здесь не эталонная.**
  Пятно доходит до пика ровно на `opacity`, а поверх пятна лежат обои, поэтому худший
  пиксель — это худший стоп рампы под пятном, накрытый штрихом узора. На нём
  `--text-muted`, `--text-accent` и `--text-accent-hover` обязаны остаться ≥ 4.5:1:
  `0.22 → 5.01:1` (dark), `0.18 → 4.79:1` (light), `0.13 → 5.15:1` (cyberpunk).
  Сила эталона (0.22, на креме 0.28) на кремовой теме даёт 4.28:1, а в
  киберпанке 3.83:1 — у страницы программы плотный текст прямо на земле (`.eyebrow`,
  мета карточки в мобильном списке), чего у new-tab страницы эталона почти нет. Считает
  это `tests/lib/ground.test.ts`, а не проза: числа в комментариях `tokens.css` — те же,
  что в тесте.

**Порядок трёх слоёв — часть контракта, и он под тестом.** Все три на `--z-decor` (−1),
порядок отрисовки задан порядком в дереве: `body::before` (ramp) → `.ground-bloom`
(свечение) → `body::after` (соты). Ramp непрозрачный, значит он обязан рисоваться первым,
а соты — поверх; свет — между ними, он полупрозрачный и по замыслу лежит на рампе, а не на
узоре. Поэтому `.ground-bloom` стоит первым ребёнком `body`: при общем `z-index` это
единственное, что задаёт его место. Обратный порядок ramp и сот закрашивает соты целиком:
проверено пиксельным диффом кадра, 69 117 px расходится, и соты видны только если убрать
верхний слой. В портфолио ровно по этой причине ramp живёт на `html` (комментарий в
`global.css:2534` — «a layer above the lattice would paint the honeycomb out»), но здесь
так нельзя: фон корня растягивается на высоту **всего документа** (18 891 px на телефоне,
7 873 px на десктопе), поэтому в пределах одного экрана 135°-градиент проходил 3–4 % рампы
и читался как один плоский синий. Фиксированный слой снимает эту зависимость и оставляет
соты сверху. Обмен слоёв местами молча проходит и сборку, и все браузерные тесты, поэтому
порядок привязан юнит-тестом `tests/lib/ground.test.ts`: он читает `tokens.css` и требует,
чтобы ramp лежал в `body::before`, маска сот — в `body::after`, а свет — между ними по
дереву `Base.astro`.

`background-attachment: fixed` не используется сознательно: на iOS Safari он нестабилен.
Фиксированный элемент даёт тот же результат без этого свойства и растрируется один раз.

**Следствие, которое было неочевидно: липкие полосы перестали быть невидимыми.** Ramp
на `html` был почти плоским внутри экрана, поэтому `background: --background-primary`
у шапки залов, колонки времени и полосы табов дня совпадал с фоном и полос не было
видно вовсе. С фиксированным ramp-ом тот же непрозрачный токен стал читаться
прямоугольником другого оттенка. Полупрозрачная полоса с `backdrop-filter` проверена и
отброшена: под полосой проезжает текст карточек, и он читается сквозь стекло даже при
20 px размытия — дефект хуже исходного. Поэтому у полос теперь своя поверхность —
`--surface-sticky: var(--card-background)`: тёмные полосы в двух тёмных темах и
кремовая в светлой, та же пара, что у карточек. Полоса читается шапкой таблицы, а не
дефектом заливки; на печати все три остаются белыми (`program.css`, блок `@media print`).

Все три слоя сидят на `--z-decor` (−1): они идут над канвой и под всем контентом,
поэтому не подкрашивают текст и не перехватывают клики. Печать, `forced-colors` и
`prefers-contrast: more` гасят декор тем же медиазапросом, что и остальные градиенты —
там страница остаётся плоским `--background-primary`, и липкие полосы снова сливаются с ним.
`prefers-reduced-motion` останавливает обе орбиты, оставляя слои на месте: свет остаётся
светом, просто неподвижным.

**Панель меню идёт за темой экрана.** Раньше `#site-nav` переопределял четырнадцать токенов
парой из `[data-theme="light"]` и был светлым всегда — в тёмной и киберпанк-теме меню
вспыхивало белым на тёмном градиенте. Теперь локальных переопределений нет: панель читает
те же токены, что страница.

Поверхность панели — `var(--card-background)`, а не `--background-secondary`, и это
единственное, что здесь выбиралось по замеру. В тёмной теме `--background-secondary`
(#16009f) — ровно 55 %-стоп `--gradient-page`, то есть цвет того, что лежит под панелью:
шов исчезает (≈1.2:1 к канве). `--card-background` в тёмной теме (#0d0068) темнее рампы
(1.49:1), в светлой кремовый.

**В киберпанке этот выбор не даёт отделения по цвету, и это записано, а не спрятано:**
там `--card-background` = `--background-secondary` = `#232327` — тот же 55 %-стоп рампы,
то есть панель совпадает с фоном под собой (≈1.14:1). Слой в этой теме держат ребро
(`border-inline-end: var(--border-strong)`, 3.18:1) и тень-свечение `--shadow-color`
(`rgba(255, 133, 105, 0.15)` — неоновое свечение, язык этой темы, а не тень). Отдельного
токена поверхности под панель не заводится: любое значение из палитры киберпанка —
это либо стоп рампы, либо соседний стоп.

**Границы контролов внутри панели — `--border-strong`, а не `--border-color`.** На панели
киберпанка волосяная линия даёт 1.79:1: рамка кнопки «Избранное» и «Сменить тему» —
единственный признак того, что это кнопки, и она не добирала до нормы 3:1 (WCAG 1.4.11).
У `--border-strong` к той же панели 3.18:1, к панели тёмной темы 6.24:1, к кремовой
светлой 4.70:1 — минимум по темам 3.18:1, и он и есть тот, что держит норму.

**Ховер пункта меню — нейтральная примесь, не `--interactive-hover`.** В тёмной теме
`--interactive-hover` (#0d0068) равен `--card-background`, то есть фону панели: подложки
не появлялось вовсе. `color-mix(in srgb, var(--text-normal) 9%, transparent)` работает во
всех трёх темах — в тёмных светлит, в светлой затемняет.

**`color: var(--text-normal)` у панели — страховка, а не текущая необходимость.** Пока
панель перекрашивалась в светлую, без этого правила узел без собственного `color`
(сноска в подвале) наследовал кремовый `#f8f2da` от `body` и оказывался кремовым на
кремовом, контраст ≈1. Сейчас панель и страница делят одну тему, `body` уже задаёт тот же
цвет, и правило ничего не меняет. Оно оставлено, чтобы повторная смена поверхности панели
не воскресила тот же дефект молча — и это ровно тот класс, который ни сборка, ни тесты не
ловят.

## 6. Карточка и модалка: доступность вместо «div с обработчиком»

- Карточка не имеет `tabindex`: модалку открывает настоящий `button.talk-card__title-btn`
  вокруг заголовка. Это даёт фокус, `Enter`/`Space` и имя для скринридера бесплатно.
- «Подробнее» рендерится только там, где текст реально не влезает в кламп (порог в коде —
  `theses.length > 150`, под него попадают 80 карточек из 91, а на первом дне получается
  33 кнопки). Кнопка без видимого эффекта хуже её отсутствия.
- Модалка: `role="dialog"`, `aria-modal`, фокус-трап по Tab внутри диалога, `Esc`, клик по
  подложке, возврат фокуса на кнопку-триггер, `body.is-modal-open` держит лок скролла.
- Тексты из данных попадают в DOM только через `textContent`/`createElement`: `innerHTML`
  в клиенте не используется ни разу.
- Изображения с чужого CDN получают `referrerpolicy="no-referrer"` и проходят проверку
  «только `https:`» — поле из чужого API не должно стать beacon'ом.

## 8. Пути строятся от `BASE_URL`, шрифты идут через бандлер

Первая версия этого переписывания жёстко писала `/program.json`, `/fonts/…` и `/day/2/` —
работало только на корне домена. При `base: "/mm-program-page"` всё ломалось: ссылки дней
склеивались в `/mm-program-pageday/2/`, `/program.json` и шрифты уходили в 404, favicon тоже.

Что сделано: `BASE_URL` в `src/lib/program.ts` (нормализованный `import.meta.env.BASE_URL`
с фолбэком для `bun test`), `dayHref` и клиентский `fetch` строятся от него, favicon
префиксуется в `Base.astro`, а шрифты переехали из `public/fonts` в `src/assets/fonts` —
только оттуда Vite переписывает `url()` на хешированный путь с префиксом. Проверка не «на
глаз»: сборка с `base` прогнана в Chromium, табы ведут на `/mm-program-page/day/2/`, модалка
открывается (значит `/program.json` отдался 200), шрифты загрузились 200, консоль чистая.

Цена: `public/fonts` больше не годится как способ положить шрифт, и `?track=` резолвится по
чипам, а не через `resolveTrack` из ядра (та функция тянет статический `PROGRAM` и втянула бы
слепок в клиентский бандл ради одного сравнения).

## 10. Мобильный экран: список вместо сжатой сетки

До 767.98 px в кадр помещается один зал. Пять колонок залов на 390 px дают ширину
содержимого 2020 px против 358 px вьюпорта — около 5.7× того, что видно, уезжает за
горизонтальный скролл, а человек видит колонку «Молекула» и ничего больше. Поэтому
мобильная модель — не сжатая сетка, а **хронологический список**.

Переключает её только CSS, разметка одна. `.program-grid__content` становится
`display: flex; flex-direction: column`, а DOM уже идёт в порядке строк (время → доклады
строки по залам → следующее время), поэтому список получается бесплатно, а inline
`grid-area` в не-grid контейнере инертен. Второго HTML, второго маршрута и второй копии
карточек нет; без JS список читается целиком.

| Что | На мобильном | Почему так |
| --- | --- | --- |
| `.program-grid` | `overflow: visible`, без `min-inline-size` | скроллить нечего: контент живёт в одной оси |
| `.program-grid__content` | flex-столбец | строки сетки исчезают, остаётся один столбец |
| Шапка залов | `display: none` | столбца залов больше нет — подписывать нечего |
| Зал | бейдж `.talk-card__hall` в карточке | зал — свойство доклада, а не координата; на десктопе бейдж скрыт, там зал читается из шапки |
| Баннер | скрыт у карточки с картинкой | баннер 4:3 оттесняет текст на пол-экрана, а картинку всё равно видно в модалке |
| `.talk-card--compact` | `.talk-card__media` остаётся | в нём `h3` с кнопкой заголовка: скрыть — оставить 13 карточек без заголовка и без входа в доклад |
| Время в карточке | чип `.talk-card__time` в шапке | разделитель группы уезжает из вьюпорта при скролле длинного дня; бейдж в самой карточке держит время при ней |
| Трек в карточке | строка `.talk-card__track` под чипами | трек в сетке задан колонкой, в списке колонки нет — координата терялась у 78 карточек с баннером |
| Разделитель времени | заголовок группы, не липкий (§18) | полоса висела над карточками ради одной подписи; время держит чип в шапке карточки |

Липкая цепочка — две ступени: `header.nav-mobile` (0…65 px) → `nav.day-tabs` (65…126 px;
61 px = таб 44 + два паддинга по 8 + линия 1). Смещение второй ступени — `--nav-mobile-h`,
поэтому табы не заезжают под шапку. Третьей ступени больше нет: §18 снял липкость
разделителя времени, а вместе с ней и токен `--mm-day-tabs-h`.

**«Избранное» — второй, независимый фильтр.** Чип `button.track-chip[data-fav-filter]`
стоит первым в `.track-chips` и намеренно не несёт `data-track`, поэтому селектор чипов
трека его не подхватывает, а счётчик в чипе живёт рядом с `[data-favorites-count]`.
Условия складываются по «И»: видима ячейка, у которой (трек не выбран или совпал) и
(фильтр избранного выключен или доклад в избранном). В URL попадает только `?track=`:
избранное лежит в `localStorage`, и ссылка с чужим избранным была бы ложью. В режиме
списка группа времени без видимых докладов прячет свой разделитель — заголовок без
содержимого мусорит; в сетке разделители не скрываются никогда, иначе рвётся колонка
времени.

**Цена.** Замерено в Chromium, `390×844`, день 1 (39 карточек, пять залов):

| Метрика | Сжатая сетка | Список |
| --- | ---: | ---: |
| Ширина документа | 390 px, `scrollWidth` сетки 2020 | 390 / 390 px, горизонтального скролла нет |
| Помещается в кадр | один зал из пяти | вся ширина карточки |
| Скрыто за горизонтальным скроллом | ~5.7× содержимого | 0 |
| Высота документа | 7 479 px | 18 325 px |

В списке 39 карточек в один столбец, высота карточки 316…550 px, средняя 421. Документ
стал в 2.5 раза выше — это плата за то, что каждая карточка видна целиком. Скрытые 5.7×
ширины в сетке не были экономным экраном: там был один зал и надежда, что человек

### Осознанные решения волны 3

- **Фильтр по треку на телефоне — не ряд чипов.** *(Способ выбора с тех пор сменился:
  `select` снят, трек выбирается из меню в шапке — §17, §21. Причина «не ряд чипов»
  осталась в силе.)* Двенадцать подписей
  занимают 2147 px: в строку 358 px они не влезают, перенос даёт 8 строк / 252 px над
  карточками, а перенос в 10 px — 5 строк, но кегль мельче принятого минимума. Поэтому
  на ≤ 767.98 px чипы треков скрыты, а тот же `activeTrack` выбирается системным списком
  в одну строку 36 px внутри `label.track-select` (чип «Избранное» остаётся чипом).
  Оба вида читают и пишут одно состояние: `aria-pressed` скрытых чипов продолжает
  обновляться, `change` списка зовёт тот же `setActiveTrack`.
- **Маска-градиент на вкладках не нужна.** Ряд вкладок на 320 px встаёт в строку целиком
  (тест `20`), скрывать fade-краем нечего; лишний слой градиента не заводим.
- **Крестик модалки — `sticky` с `inset-block-start: 0`.** `absolute` уезжал вместе с
  контентом при прокрутке длинного описания. `sticky` отсчитывается от content-box,
  поэтому `var(--space-3)` = 12 px складывались с 16 px паддинга диалога — кнопка висела
  в 29 px от края; ноль возвращает её к самому верху.
- **`flex: none` у крестика.** В колоночном flex-контейнере кнопка сжималась до 22 px
  на длинном докладе — цель нажатия ломалась. `flex: none` держит видимый круг 40 px
  (44 px с псевдоэлементом).
- **Два тумблера темы.** Тема перестала зависеть от drawer'а: на мобиле открывать меню
  ради смены темы — лишний шаг. Старый тумблер остался в `.drawer-foot`, новый — в
  `div.nav-top-actions` шапки; оба несут `data-theme-toggle`, поэтому слушатель один
  и делегирован.
- **`history`-стек для слоёв.** Модалка и drawer открываются с `pushState`, системная
  «Назад» закрывает слой через `popstate`; пользовательское закрытие делает
  `history.back()`, но только если верхняя запись ещё наша (`mmLayerToken`) — иначе
  `back()` увёл бы со страницы.
- **`inert` через `MutationObserver`, а не из клиента.** Модалка — отдельный
  Astro-компонент, а класс `body.is-modal-open` ставит `program-client.ts`. Наблюдатель
  за `class` держит компонент независимым от порядка инициализации и не требует
  экспортировать из клиента функцию «заблокируй фон». Снятие `inert` синхронно в
  capture-фазе возвращает уже `inert`-drawer'у его прежнее состояние.
- **`html:has()` для iOS.** `overflow: hidden` на `body` не гасит «резину» корневого
  скроллера в WebKit; дубль `html:has(body.nav-open)` и `html:has(body.is-modal-open)`
  адресует корневой скроллер напрямую. `:has()` уже в базовой линии проекта.

## 11. Иконка темы: морф вместо статичной луны

Тумблеров темы два (шапка и drawer), тема циклится dark → light → cyberpunk, но в разметке
на все три состояния стояла одна луна: `.astro` рендерится на билде и о `localStorage` не
знает, а клиент иконку не трогал. В светлой теме луна врала о состоянии.

**Решение.** `morphicons@1.7.0`, subpath `morphicons/dom`: `createMorph(path, icon)` на каждый
тумблер, `morphTo` в делегированном обработчике. Геометрия трёх иконок живёт в одном месте —
`src/lib/theme.ts` (`THEME_PATHS` / `THEME_ICONS`): разметка рендерит `d` оттуда, клиент берёт
оттуда же готовую иконку. Передаются именно memoised `IconNode`, а не сырые `d`-строки:
драйвер кеширует разбор и план в `WeakMap` по идентичности объекта, а строка шла бы мимо кеша
и пересобирала план на каждый клик. Ту же карту разметка кладёт в `data-theme-icons`, откуда
её достают инлайновый fallback и предрисуночный скрипт, — поэтому иконка остаётся правдивой
без клиентского модуля. Первая иконка ставится без анимации, поэтому сохранённая тема сразу
даёт своё состояние.

**Почему не `morphicons/astro` + `element`.** Потребовал бы заменить `<path>` на
`<MorphIcon>` в двух компонентах, весит 8.9 КБ gzip вместо 7.1 и добавляет второй
скрипт-чанк. `dom` живёт в уже подключённом модуле и разметку не меняет. Без JS страница
всегда остаётся в тёмной теме по умолчанию, поэтому луна в разметке там не врёт; а на `404`,
где клиентского модуля нет, светлая системная тема раньше оставляла лживую луну — это
чинит инлайновый fallback.

**Звезда избранного — не морф.** Пайплайн 1.7.0 штриховой: залитая фигура разбирается, но
в полёте читается неправильно (fill-конвейер появился только в 2.x). Поэтому контур →
заливка сделана через CSS: постоянный `fill: currentColor` + `fill-opacity: 0 → 1`. `fill`
между `none` и цветом не интерполируется, `fill-opacity` — интерполируется. Строка
`path.setAttribute("fill")` из `syncFavorites` удалена: источник состояния теперь один.

**Цена.** Клиентский чанк — 46.6 КБ raw / 17.6 КБ gzip (46 599 / 17 556 байт). Прирост дают
библиотека и сам клиент, а слепок программы в чанк больше не входит (§13), поэтому цифра
не растёт вместе с данными. HTML почти не изменился: иконки остаются в разметке, CSS вынесен
отдельными файлами, инлайновых `<style>` нет; добавились только карта иконок в
`data-theme-icons` (~0.5 КБ) и `<link rel=preload>` первого баннера.
`reducedMotion: "user"` — при системной настройке «уменьшить движение» морф заменяется
мгновенной подменой, как и остальные переходы в CSS.

**Проверено.** `bun run check` — 0 ошибок; `bun test` — 161 pass; Playwright — 38 тестов
× 3 проекта = 111 прогонов, включая прогон с выключенным JavaScript.

## 12. Языки: ручные маршруты и overlay перевода

Нужны две локали без второго фреймворка и без правки замороженного снапшота. Русская
версия остаётся первичной: `/`, `/day/N/`, `/program.json`.

**Решение.** Язык — это маршрут, а не настройка. `src/pages/en/index.astro` и
`src/pages/en/day/[n].astro` повторяют русскую раскладку (первый день — на корне локали),
`src/i18n/paths.ts` строит адреса от `BASE_URL`, `src/pages/en/program.json.ts` отдаёт
переведённый слепок. `<html>` несёт `lang` и `data-lang`, у страниц дня есть
`hreflang="ru|en"` и `x-default` → русская версия. Оболочка переводится словарём
`src/i18n/ui.ts`, контент — overlay'ем `src/data/program.en.json`.

**Почему не `i18n`-конфиг Astro.** Встроенная маршрутизация (`prefixDefaultLocale`,
`redirectToDefaultLocale`) добавила бы правила для адресов, которых у нас нет: 404 и JSON
не должны получать префикс автоматически, а первый день живёт на корне локали, а не в
`day/1/`. Ручные страницы — это четыре файла примерно по 20 строк, и адреса остаются явными.

**Почему overlay, а не перевод в `program.json`.** `bun run data:fetch` пересобирает
`program.json` побайтово из API и стёр бы переводы — та же причина, по которой отдельным
файлом живут соцсети. Overlay адресуется по id доклада и хранит только текст:
`title/short/description/lectorRoles`. Пропуск — не ошибка: `localizeTalk` возвращает
исходную русскую строку, страница рендерится с неполным переводом, а не падает.

**Почему `data-track` остаётся русским.** По этому атрибуту клиент фильтрует сетку и
связывает карточку с чипом; переведённое значение сломало бы селектор. Поэтому
`localizeTalk` переводит только текстовые поля, а подпись чипа и текст на карточке
переводятся отдельно (`trackLabel`). `localizeProgram` — отдельная функция для
`/en/program.json`: там `track`, `hall` и `days[].halls` уже переведены, потому что модалка
и `.ics` читают JSON как готовый текст.

**Машинный перевод — принятое ограничение.** Английские тексты докладов получены машинным
переводом и не сверялись с авторами; исходный русский `program.json` остаётся источником
истины. Это записано в `CONTRACT.md`, чтобы расхождение не выдавалось за редактуру.

**Цена.** Overlay — 146 379 байт raw / 43 312 байт gzip (`gzip -9 -c

## 13. Клиентский чанк: слепок ушёл из бандла

Импорт из `src/lib/program.ts` тянул за собой данные. `PROGRAM` там инициализируется на
верхнем уровне модуля, то есть это побочный эффект, который tree-shaking не убирает:
клиенту нужны были `DATE_RE`, `firstParagraph` и `BASE_URL`, а приезжал весь слепок.
Чанк весил 327 765 байт raw / 80 902 байта gzip, из них 289 049 байт — JSON.

**Решение.** Данные и функции над ними остались в `program.ts`, а типы и чистые помощники
переехали в `src/lib/program-core.ts` — модуль без единого импорта из `src/data`, который
клиент тянет спокойно. `program.ts` реэкспортирует ядро, поэтому старые импорты
`../lib/program` продолжают работать, а клиентские модули ходят в `program-core`.

**Результат.** Клиентский чанк — 46 599 байт raw / 17 556 байт gzip. Это самая большая
разовая экономия в проекте, и дала её граница модулей, а не минификация: тот же код, но
без слепка рядом.

**Сторож.** В `program-core.ts` и в клиенте стоят комментарии, которые объясняют, почему
сюда нельзя импортировать `program.ts`, а этот раздел — вторая половина правила.
Комментарий клиента, который обещал, что слепок не поедет в браузер, теперь говорит правду.

## 14. Мобильная шапка карточки и панель меню: координата доклада целиком

Мобильная модель (§10) строилась вокруг экономии высоты: баннер скрыт, время отдано липкому
разделителю группы, трек жил только в медиа-блоке компактной карточки. На практике это
стоило дороже, чем экономило: разделитель уезжает из вьюпорта при прокрутке длинного дня, а
у 78 карточек из 91 трек отсутствовал в DOM вовсе — блок медиа скрыт, а вместе с ним и
название трека. Свёрнутая карточка читалась как «доклад без координаты».

**Решение.** Шапка карточки на ≤ 767.98 px перестала быть оверлеем на баннере (баннера там
нет) и стала обычной строкой метаданных в потоке: `grid` из трёх частей — чип времени, чип
зала и трек под ними на всю ширину. Трек — новый элемент `.talk-card__track`, отрендеренный
во всех карточках; на десктопе он скрыт правилом, а не отсутствием в разметке. Название
трека держит две строки клампа: одна строка обрезала бы его наполовину — самое длинное имя
(«СЕМАНТИЧЕСКИЙ СЛОЙ И АНАЛИТИЧЕСКИЕ АГЕНТЫ») занимает ровно 32 px, то есть две строки в
324 px.

**Цена.** Шапка выросла, но «замороженной» высоты, которую пришлось бы пересматривать, нет:
на мобиле `article.talk-card` и так `block-size: auto`, минимум строки сетки не действует.

**Избранное из панели.** «Избранное» в подвале меню было `<p>` со счётчиком — не элемент
управления. Теперь это `button.drawer-favs[data-fav-drawer]`: закрывает меню, включает тот
же фильтр, что чип `[data-fav-filter]`, и прокручивает к сетке. Состояние читается через
`aria-pressed` на обеих кнопках из одной точки (`setFavoritesOnly`). Кнопка рендерится
только на страницах дня (`favorites={Boolean(dayOrdinal)}`), как и поиск: на 404 нет
клиентского модуля, и кнопка была бы мёртвой.

**Иконки.** Каждая строка панели получила иконку: дни — календарь, ссылки — дом / папка /
конверт (существующие токены `--nav-*`), избранное — звезда. У дней и избранного геометрия
добавлена в `site.css`, а не в `program.css`: панель живёт и на 404, где стили программы не
грузятся. Приём тот же, что у ссылок шапки, — маска на `::before`, поэтому разметка остаётся
текстом и скринридер читает только подпись.

**Проверено.** `bun run build` — 7 страниц; `bun test tests/lib` — 151 pass;
`bunx astro check` — 0 ошибок; `bun run test:built` — 114 прогонов (3 проекта). Тест `09`
переписан под новый контракт (время, зал и трек видимы; кламп трека равен 2), тест `19`
дополнен проверкой, что на десктопе трек и зал остаются `display: none`. `CONTRACT.md`
(таблица мобильной модели и DOM-снимок) и этот раздел правятся вместе с CSS — иначе гейт
защищал бы прежний дизайн.

## 15. «Граф докладов» в шапке: три поверхности одного пункта

Программа и граф докладов — две проекции одного набора из 91 доклада: здесь расписание по
залам, там треки, темы и связи между докладами. Первая версия этого решения (v2.0) вела
пункт в портфолио и держала его **только в панели меню**. Две вещи в том решении
перестали быть верными: граф переехал в этот же сайт (`§20`), а шапка за это время получила
звезду избранного (`§16`) и меню треков (`§17`) — то есть перестала быть «полосой на три
ссылки портфолио».

**Решение.** Один пункт — три поверхности, и ни на одной он не дублируется:

| Ширина | Где | Почему здесь |
| --- | --- | --- |
| ≥ 1024 px | текстовая ссылка `a.nav-link--talks` первым пунктом `ul.nav-inline`, иконка `--nav-talks` | полоса видна и вмещает четыре подписи: 1180 px контента против ~390 px ссылок |
| 480–1023.98 px | иконка `a.nav-icon-btn.nav-graph` в `div.nav-top-actions` | полосы ссылок нет (уходит в drawer), но шестая иконка влезает: 7 × 44 + 6 × 8 = 356 px против 448 px контента на 480 px |
| ≤ 479.98 px | нет — пункт остаётся в панели меню | пять целей по 44 px занимают 285 px из 296 возможных на 320 px; шестая не влезает физически |

Переключатель языка на странице графа ведёт на **граф** другой локали (`talksHrefFor`), а не
на первый день: иначе кнопка уводила бы читателя с той страницы, которую он читает.

**Цена.** Одна лишняя поверхность и один медиазапрос вместо нуля. Инлайновая полоса теперь
несёт четыре подписи, и самая длинная из них — «Граф докладов». Замер на 1280 px: полоса
~400 px, справа группа из трёх кнопок; зазор до бренда остаётся ~350 px, переносов нет.

**Проверено.** Тест `35` (`tests/built/talks.spec.ts`) проверяет видимость нужной
поверхности на трёх ширинах проектов и `aria-current="page"`; `37` — что на 320 px вбок
скроллится только граф.

## 16. «Избранное» в шапке: звезда первой в группе действий

Личный фильтр жил в трёх местах: чип первым в полосе треков, кнопка в панели меню и звезда на
карточке. На телефоне чип и кнопка уезжают вверх вместе с тулбаром и панелью, а на десктопе
звезда в шапке была единственным способом увидеть «сколько у меня отмечено», не открывая меню.
Решение: звезда со счётчиком первой в `div.nav-top-actions` (`[data-fav-header]`, только на
страницах дня — на `404` фильтровать нечего).

**Это переключатель, а не «показать».** Кнопка в панели всегда включает фильтр (она закрывает
меню и уводит к списку), а звезда в шапке живёт на виду, поэтому второй клик обязан возвращать
весь список — иначе состояние «включено» нечем выключить с того места, где его включили.
Отсюда `aria-pressed` и заливка акцентом с `--accent-ink` — ровно как у выбранного чипа трека
(`.track-chip[aria-pressed="true"]`): это один фильтр и одно состояние, в двух местах оно не
должно выглядеть по-разному.

**Число одно на два места.** Счётчик в шапке носит тот же `data-favorites-count`, что и счётчик
в панели, и `syncFavorites` обновляет все узлы с этим атрибутом. Второй атрибут
(`data-fav-header-count`) завёл бы вторую точку обновления, и шапка отставала бы от панели до
перезагрузки — это и ловит тест `29`. Следствие для тестов: строгий локатор
`[data-favorites-count]` теперь находит два узла, поэтому место названо явно
(`#site-nav …`, `header.nav-mobile …`).

**Имя кнопки — подпись плюс число.** Иконка без текста дала бы скринридеру голое «0»; скрытая
подпись (`visually-hidden`, «Избранное» / «Favorites») плюс видимое число дают «Избранное 3»,
а `title` объясняет действие.

**Цена — имя в шапке на телефоне.** Пять кнопок по 44 px с зазорами просят 252 px; на 360 px
контентной полосы 336, то есть под имя остаётся 84 против нужных 108 — оно обрезалось бы
многоточием. Поэтому на ≤ 479.98 px шапка страницы дня показывает монограмму: имя остаётся в
`aria-label` ссылки, в шапке drawer'а и в подвале. Правило привязано к самой звезде
(`header.nav-mobile:has([data-fav-header])`), а не к ширине: на `404` кнопок три, имя там
помещается, и скрывать его незачем; без поддержки `:has()` разметка не ломается — имя просто
ужмётся флексом, как ужималось до этой правки. До неё имя помещалось на 390 (108 px ровно) и
пропадало на 320 само, сжатием; теперь это правило, а не побочный эффект. Высоту цели нажатия
у монограммы подняли до 44 px — ширина 25 px остаётся потолком (на 320 px под бренд всего
36 px), но вертикальная ось полосы позволяет отдать ссылке полноценные 44.

**Прокрутка к сетке — только когда её нет в кадре.** Фильтр из шапки или панели применяется
мгновенно с любого места страницы (шапка липкая), и без прокрутки это выглядит как «ничего не
произошло». Но если верх сетки уже виден, scroll не трогаем — иначе каждое переключение дёргало
бы страницу. Клик по чипу не прокручивает вовсе: чип стоит прямо над списком.

**Проверено.** `bun run check` — 0 ошибок, `bun run build` — 7 страниц; в собранном HTML
`/` — 40 вхождений контура звезды (39 карточек + шапка), то есть глиф не разъехался после
переноса в `src/lib/icons.ts`. Замер в браузере на 320 / 360 / 390 / 430 / 768 / 1280 px:
везде пять кнопок по 44 px, `scrollWidth − clientWidth = 0` у документа и `0` у самой шапки;
на ≤ 479.98 имя скрыто (`display: none`), на 768 и выше — на месте; на `404` кнопок три,
звезды нет, имя показано, скролла вбок тоже нет. Нажатие: `aria-pressed` переключается, фон
становится `--text-accent`, чернила — `--accent-ink`, остаётся одна видимая карточка, чип
трека показывает то же состояние, после перезагрузки состояние приходит из `sessionStorage`.
Тест `29` держит это в браузерном наборе (37 тестов × 3 проекта = 111 прогонов).

## 17. «Все треки» в шапке: меню из 12 пунктов, а не кнопка-сброс

Трек выбирался только чипами в тулбаре, а тулбар не липкий: отфильтровав список и уехав
вниз, читатель возвращался к полному расписанию пешей прогулкой наверх. Липкая шапка уже
носит фильтр избранного (звезда), поэтому фильтр трека получил там же кнопку.

**Первая версия была неверной, и это видно только глазами.** Кнопка снимала фильтр — то есть
при полном списке не делала ничего. Со стороны это читалось ровно как «кнопка не работает»,
и именно так и пришло: с замечанием от читателя, а не от теста. Правильная модель —
раскрывающийся список: кнопка открывает те же 12 пунктов, что и чипы под вкладками дня
(«Все треки» + 11 треков), поэтому выбор трека из шапки — один тап, а не прогулка к тулбару.

**Одно состояние, три поверхности.** Пункты меню, чипы и телефонный `select` пишутся одним
`setActiveTrack`: `aria-pressed` на пунктах, `data-active` (заливка акцентом) на кнопке,
`aria-pressed` на чипах, значение `select` и `?track=` в URL. Состояние из URL применяется
тем же проходом при загрузке — иначе разметка («Все треки» нажата) оставалась бы единственным
источником правды, и `data-active` у кнопки не появлялся бы вовсе (тест `30` поймал именно
это, когда кнопка была ещё сбросом).

**Панель — не модалка.** Без фокус-трапа: закрывается по Esc (фокус возвращается на кнопку),
клику мимо и выбору пункта; `aria-expanded` на кнопке, `role="group"` с подписью группы
фильтров внутри. На ≤ 767.98 px панель становится листом под шапкой во всю ширину: от кнопки
она свисала бы за левый край (замер: `left = −98` при 390 px), потому что кнопка стоит в
правой группе, а 320 px шире остатка вьюпорта. Пункт — цель 44 px по высоте.

**Цена — ссылка на язык уехала в drawer.** Пять кнопок в полосе 320 px занимают 252 px, под
монограмму и зазоры остаётся 11 px: шестая не влезает (6 × 44 + зазоры > 296). Убирать
пришлось язык, а не тему и не поиск: тема — частая операция (это записано в §11), поиск —
вход в контент, а язык выбирают один раз, и та же ссылка с глобусом и кодом цели ждёт в
`.drawer-foot`. Ниже 520 px шапка показывает монограмму вместо имени: шесть кнопок и имя
требуют 461 px контентной полосы. Правило привязано к кнопке треков (`:has`), поэтому на
`404`, где кнопок три, имя остаётся при любой ширине.

**Проверено.** Тест `30`: 12 пунктов, «Все треки» нажат без фильтра, выбор пункта фильтрует
список и пишет `?track=`, чип в тулбаре повторяет состояние, кнопка получает `data-active`,
Esc закрывает и возвращает фокус, клик мимо закрывает, сброс возвращает 39 карточек и чистый
URL, состояние из `?track=` подсвечивает нужный пункт. Прогон в трёх проектах (1280 / 320 /
390) — значит кнопка есть и на телефоне. Тест `35` переписан: на 320 px ссылка языка скрыта
в шапке и видна в открытом drawer'е.

## 18. Липкая лента со временем снята

На ≤ 767.98 px разделитель группы времени был третьей ступенью липкой цепочки (шапка →
табы дня → разделитель). Полоса занимала 44–48 px под табами ради одной подписи «11:00», а
внутри длинной группы не двигалась, то есть висела над докладами 12:10, пока читатель шёл
по группе 11:00. Высоты на телефоне дорогие: 390×844 — это 46 % полосы под липкую шапку и
табы, если считать с разделителем.

**Решение.** `.program-grid__time-cell` в мобильном блоке стал `position: static`: он остался
заголовком группы (между группами), но уезжает вместе со своей группой. Время при докладе
при этом не теряется — его несёт чип `.talk-card__time` в шапке карточки, который появился в
§14 именно потому, что разделитель уезжает. Токен `--mm-day-tabs-h` (высота полосы табов,
нужная только третьей ступени) удалён; `--mm-day-tabs-pad-block` остался — он задаёт паддинг
самой полосе.

**Что осталось от цепочки.** Две ступени: `header.nav-mobile` → `nav.day-tabs`, смещение
второй — `--nav-mobile-h`. Горизонтальная липкость колонки времени на десктопе не тронута:
это другая ось и другой скроллпорт (`--mm-time-col` внутри `overflow-x: auto`).

**Тесты переписаны, а не удалены.** `16` и `24` больше не ищут ступень под табами; они
проверяют обе половины решения: `getComputedStyle(time).position !== "sticky"` и «разделитель
ушёл выше табов» — плюс прежнее «табы стоят ровно под шапкой». Без второй половины тест
проходил бы и на странице, где липкость сломана целиком.

## 19. Картинки: замер, что сделано и что осталось

**Замер до правки.** Страница первого дня: 65 `<img>` (33 баннера + 32 аватарки).
Полный проход по 65 адресам: **26.2 МБ**; сборка в Chromium с прокруткой всего дня давала
10.2 МБ на десктопе 1280×900 и 13.8 МБ на 390×844. Раскладка потерь:

- **аватарки** (`storage.yandexcloud.net`, 36 px в CSS) — 528 КБ в среднем, до 1.2 МБ;
  на день это 7.5–13.8 МБ, то есть почти весь вес;
- **баннеры** (`mm-graphics.netlify.app`) — 324 КБ в среднем, PNG 1200×900 при карточке 391 px;
- **баннеры** (`img.matemarketing.ru`) — 285 КБ в среднем; хост отвечает 1.7–25 с и в замере
  в браузере первый баннер (он же LCP с `fetchpriority=high`) не загрузился вовсе
  (`naturalWidth = 0`).

**Что можно было сделать и почему именно так.** Ресайз есть ровно у одного хоста:
`mm-graphics.netlify.app` — это сайт на Netlify, у которого работает Image CDN
(`/.netlify/images?url=…&w=…&fm=webp&q=…`; 300 КБ PNG → 37 КБ при `w=800`, 15 КБ при `w=400`).
У `storage.yandexcloud.net` параметров нет (`?w=72` и `?width=72` возвращают те же байты), а
проксировать чужие хосты через Netlify нельзя — `url=https://…` отвечает 400 «not an allowed
pattern». Значит для аватарок единственный путь — сделать вариант самим.

**Сделано.**
- `src/lib/images.ts`: `bannerSources()` отдаёт `srcset` (400w/800w, WebP q72) только для
  Netlify-хоста, для остальных — прежний `src`. Предзагрузка первого баннера берёт тот же
  объект (`preloadBanner` → `imagesrcset`/`imagesizes`), иначе браузер качал бы два файла.
- `scripts/optimize-photos.ts` (+ `prebuild`, `bun run photos`): качает аватарки, режет до
  144×144 (`fit: cover`, `position: attention` — лица), пишет WebP q72 в
  `public/media/lectors/<hash>.webp` и карту `src/data/photos.json`. Скрипт идемпотентен
  (имя = хеш URL), а любая сетевая ошибка не валит сборку: адрес просто не попадает в карту,
  и разметка отдаёт оригинал. 79 аватарок = **344 КБ** вместо 10.5 МБ на день.
- `photoSources()` в разметке карточки (локальный вариант, иначе оригинал).

**Чего в модалке НЕТ, и это результат ревью, а не недосмотр.** Первая версия подменяла `photo`
и в `/program.json` (`withLocalPhotos`), чтобы модалка тоже брала 144-пиксельный вариант.
Подмена ломала модалку целиком: клиент валидирует `photo` через `imageUrl()` (белый список
хостов + `https:`), относительный `/mm-program-page/media/…` там отвергается, и все 79
спикеров показывались инициалами. Поймано на ревью диффа, а не тестом: тест сравнивал выход
той же функции, которая его произвела. Откат вернул прежнее поведение — модалка качает
оригинал по действию пользователя (одно изображение, не 32 на страницу), а карточки остаются
лёгкими. Урок записан в тест: карта проверяется отдельно от диска (`photoMapEntry`), форма
локального пути — регуляркой, а не `if` с условием.
- Атрибуты баннера: `srcset` + `sizes` рядом с прежними `width/height`, `loading="lazy"`,
  `decoding="async"`, `referrerpolicy="no-referrer"`.

**После.** Тот же замер, Chromium, прокрутка всего дня: десктоп **10.22 → 0.36 МБ**,
телефон **13.75 → 0.08 МБ** (21 аватарка локально + 19 баннеров через Netlify-трансформ).
Страница стала легче в 28 раз на десктопе и в 170 раз на телефоне.

**Что осталось и почему это записано, а не спрятано.**
- 14 баннеров дня 1 (и 33 из 78 по всей программе) живут на `img.matemarketing.ru`, у которого
  нет ни ресайза, ни стабильного ответа. Локальная производная закрыла бы и их — скрипт для
  этого уже готов, — но это отдельное решение: оно тянет 78 баннеров (≈25 МБ) на каждую
  холодную сборку. Записано как следующий шаг, а не сделано молча.
- Яркость аватарок: 144 px выбраны под 36 px карточки при DPR 4 и 48 px в модалке при DPR 3;
  если понадобится ретина-2× для модалки, размер меняется одной константой в скрипте.

## 20. Граф докладов здесь, а не только в портфолио: Zettelkasten как модель данных

Портфолио строит граф тех же 91 доклада из этого слепка (`scripts/sync-talks-data.mjs` —
односторонняя выгрузка, источник здесь). Пока граф жил только там, программа оставалась
плоским списком: у доклада не было постоянного адреса, у тем — обратных ссылок, у треков —
пересечений. Читатель, пришедший за расписанием, о второй проекции не узнавал, а в
портфолио за ней надо было уходить.

**Решение.** Граф — своя страница этого сайта (`/talks/`, `/en/talks/`), собранная на
принципах Zettelkasten, и модель данных в `src/lib/talks-graph.ts`:

- **атомарность** — один доклад = один узел с ключом `t<id>`, и этот же `id` носит ячейка
  сетки на странице дня (`#t309`). **Замена (2026-11-13):** канонический адрес заметки —
  `/talk/<id>/` (EN — `/en/talk/<id>/`), а `#t309` остался `id` ячейки дня, целью обратной
  ссылки «← К расписанию» и адресом локатора `a.talk-note__where` (§22);
- **связи** — ребро `трек ↔ тема` с весом «сколько докладов несут оба»; рёбер
  «доклад ↔ доклад» нет намеренно (91 узел в force-раскладке слипается — тот же вывод, что
  и в портфолио), смысловая близость читается через общие темы;
- **обратные ссылки** — хаб темы перечисляет все заметки, которые на него ссылаются;
  у каждой заметки до четырёх «связанных» (общие темы с IDF-весом 4, тот же трек 1.6,
  соседство в зале 0.9, тот же день 0.2) и минимум одна — трёхступенчатый фолбэк
  (свой трек → тот же зал → тот же день). Симметризация best-effort: обратная ссылка
  добавляется, а предел в четыре ссылки сортируется по весу, поэтому A→B без B→A
  возможно только когда у B список уже полон — это и проверяет тест;
- **хабы** — событие → 12 треков (включая «Без трека») → 11 тем.

Темы выводятся из текста по стемам (словарь тот же, что в портфолио, плюс склейка `A/B` →
`ab`: без неё тема экспериментов теряла ровно те доклады, которые пишут её как на слайдах).
Темы считаются по русскому тексту и на `/en/`: классификатор один, переводится подпись.

**Почему SVG на билде, а не force-граф в браузере.** Раскладка детерминирована (кольца,
дуги пропорциональны числу докладов), поэтому SVG приходит в HTML: страница читается и
печатается без JS, клиентского чанка у неё нет вовсе, а `git diff` не шумит геометрией.
Подписи раскладывает пакер в `TalksGraph.astro`: 12 подписей треков ищут свободную полосу
по нормали к кругу, иначе у полюсов две соседние подписи садились друг на друга.

**Цена.** 36 КБ gzip HTML (91 заметка, 259 обратных ссылок, SVG) и ~600 строк кода
(модель + компонент + стили). Данные не дублируются: источник по-прежнему один — слепок.

**Проверено.** `bun test tests/lib` — 24 теста модели (темы и их короткие подписи, хабы,
вес рёбер, покрытие связями, инвариант симметрии, минимальная дистанция точек, границы
раскладки, детерминизм); `tests/built/talks.spec.ts` — 10 тестов собранной страницы (91 заметка с адресами, SVG и все якоря, 11 хабов тем, вход в
шапке на трёх ширинах — 1280 текст, 768 иконка, 320 меню, EN-копия с `hreflang`, скролл
только внутри графа). `bun run check` —
0 ошибок, `bun run build` — 9 страниц (снимок на момент решения; сейчас сборка даёт
191 страницу — 190 `index.html` + `404.html`).

## 21. Тулбар без дублей: «Избранное» и трек — только в шапке

К моменту этой правки одни и те же два фильтра жили в двух-трёх местах: чип «Избранное»
первым в полосе треков, звезда в шапке (`§16`), кнопка в панели (`§16`), меню треков в шапке
(`§17`) и нативный `<select>` в тулбаре для телефона. На 320 px тулбар занимал три строки над
карточками — ровно там, где экран дороже всего.

**Решение.** На ≤ 767.98 px полоса `div.track-chips` скрыта целиком, а `label.track-select`
удалён из разметки совсем (он и на десктопе был `display: none`, то есть существовал только
как мобильный дубль меню в шапке). В тулбаре остаются счётчик и экспорт — одна строка.
Узлы чипов из DOM **не** удалены: `[data-fav-filter]` владеет состоянием фильтра и
восстанавливает его из `sessionStorage` после перезагрузки (`initFavFilter` выходит по
`!chip`), а `button[data-track]` служит клиенту списком допустимых треков — по нему
`setActiveTrack` проверяет `?track=`. Их скрывает CSS, а не разметка.

**Цена.** На десктопе полоса чипов осталась как была (там трек выбирают одним кликом, а не
из меню). На телефоне смена трека — два тапа (меню → пункт) вместо одного системного пикера,
но состояние теперь одно на всю страницу и не расходится между поверхностями.

**Проверено.** Тест `38` (`tests/built/talks.spec.ts`): на 320 px полоса скрыта, чип
избранного есть в DOM и невидим, `[data-track-select]` отсутствует, а звезда и меню треков
в шапке работают. Общие тесты `05`, `17`, `18` переписаны на хелперы `chooseTrack` и
`favoritesControl`, которые берут видимое управление на текущей ширине.

## 22. «Связанные» в карточке: сеть заметок заходит в расписание

Граф (§20) знал про связи между докладами, но узнать о них можно было только уйдя на
`/talks/`. Читатель, который пришёл за расписанием, оставался в плоском списке: у доклада
были темы и соседи, но об этом не сообщал никто.

**Решение.** В карточке доклада — две ссылки на связанные доклады
(`div.talk-card__related` → `a.talk-card__related-link`), под кнопкой «Подробнее». Связи
считает та же модель, что и страницу графа (`relatedNotes` в `lib/talks-graph.ts`),
поэтому расходиться двум поверхностям негде: один расчёт — два места показа.

**Почему якорь, а не `?talk=`.** У заметки уже есть постоянный адрес — `/day/N/#t<id>`
(§20). Второй способ открыть тот же доклад (`?talk=<id>`) завёл бы второй адрес: один
редиректит в модалку, другой ведёт к карточке. Внутри дня ссылка становится обычным
переходом по якорю (стык `.page :target` даёт отступ под липкую шапку), между днями —
переходом на страницу нужного дня. Работает без JS.

**Замена (2026-11-13).** Канон сменился: адрес заметки — `/talk/<id>/` (EN —
`/en/talk/<id>/`), один на страницу, поиск, «Связанные», точки графа и хабы тем. Ссылки
`a.talk-card__related-link` и `a.talk-note__link` ведут на `TalkNote.hrefTalk`
(`BuildOptions.talkHrefOf`); `#t<id>` на странице дня остался целью обратной ссылки
«← К расписанию» и адресом локатора `a.talk-note__where`. Параметр `?talk=<id>` удалён
вместе с `talkHref()` и `initDeepLink()`, тип `TalkOpenSurface` сведён к `"card"`. Держат
тесты `talks.spec.ts` 31–34 (`hrefTalk`), `program.spec.ts` 40 (`/talk/\d+/$`) и
`talk-pages.spec.ts`.

**Почему две ссылки и строка на каждую.** Карточка в сетке ~254 px шириной, полное
название занимает 3–4 строки. Первая версия блока была одной строкой текста с общим клампом
на две строки — и в неё влезала одна ссылка, а вторая оставалась в DOM невидимой: фокус
уходил в обрезанный текст, а скринридер читал ссылку, которой нет на экране. Поэтому каждая
ссылка — блочная строка с `text-overflow: ellipsis`: что видно, то и есть, полное название
живёт в `title` и в карточке-цели. Две, а не три: строки сетки `minmax(520px, auto)`
выравнивают высоту по самой высокой карточке, и блок дороже ~50 px поднимал бы весь ряд.

**Цена.** +50 px на карточку (проверено: `scrollHeight` карточки остаётся равен
`clientHeight`, обрезки нет) и 76 ссылок на первом дне — 14.6 КБ HTML, ноль клиентского
кода. Пустой блок не рендерится вовсе: у доклада без связей его нет (модель гарантирует
минимум одну, но разметка не полагается на это).

**Проверено.** Тест `40` (`tests/built/program.spec.ts`): блок у всех 39 карточек, 1–2
ссылки, ни одна не ведёт на себя, адрес — `/talk/<id>/` (тест ожидает `/talk/\d+/$`),
блок не выходит за границу карточки. Юнит-тест модели: у каждой связи есть постоянный
`hrefTalk`, совпадающий с каноническим адресом заметки. `bunx astro check` — 0 ошибок,
`bun run build` — 191 страница (190 `index.html` + `404.html`), `bun run test:built` — 195 прогонов.

## 23. CI: гейт карты фотографий стоит до мутирующего шага

**Что было.** `.github/workflows/deploy.yml` запускал `bun run build` раньше `bun run test`.
`prebuild` (`package.json:9`) вызывает `scripts/optimize-photos.ts`, который перезаписывает
отслеживаемый `src/data/photos.json` — карту «оригинал → локальный webp». То есть гейт
`tests/lib/images.test.ts:65` проверял файл, который шаг перед ним только что перезаписал,
и результат зависел от сети до чужого CDN.

**Что случилось.** Прогон `43417561918`: портрет 11 371 320 байт не прошёл под прежний лимит
8 МБ, `[photos] skip … too large`, ключ выпал из карты, тест покраснел на
`images.test.ts:76` с советом «запусти `bun run photos` и закоммить» — при том что ключ
в репозитории был. Диагностика уводила в ложную сторону.

**Замена (2026-11-13).** `bun run test` перенесён выше `bun run build`. Тест сам объявляет
свой предмет как **закоммиченную** карту, разъезжающуюся с `program.json`
(`images.test.ts:12-16`), а скрипт объявляет сетевую ошибку нефатальной
(`scripts/optimize-photos.ts:17-19`). После перестановки проверяется ровно то, что обещает
тест: карта из репозитория против `program.json`, без сети.

**Почему не иначе.** Вариант «тест читает отдельный артефакт» требует нового файла, правки
импорта `src/lib/images.ts:3` и `.gitignore` — втрое больше диффа при том же остаточном
риске. «Оставить как есть» — fail-closed на посторонних коммитах, что провоцирует запрещённые
обходы (`|| true`, ручной rerun). «Отдельный шаг `bun run photos` перед тестом» оставляет
сетевой гейт и добавляет шаг.

**Остаточный риск (принят).** Сбой CDN на сборке → для части аватарок деплой отдаёт
оригиналы: `src/lib/images.ts:93-103` при отсутствии локального файла возвращает исходный
URL. Страница не ломается (404 нет), вес растёт, в логе сборки видно `пропущено N`.
Дефект порядка шагов закрыт; сетевой риск не закрыт сознательно — `public/media/` в
`.gitignore:12`, кэша нет, каждый прогон качает 79 файлов заново.
